# DRCS字形の対応一覧

字幕本文のDRCSを、受信ビットマップと属性から計算した64bitハッシュが対応表と一致する場合だけUnicodeへ変換します。登録対象は36×36・30×30・18×36・15×30・18×18・15×15の2bpp、および16×18の1bppです。外字コードの固定置換、画像の拡縮・間引きによる類似判定は行いません。

## 対応字形

変換キーには64bit FNV-1aハッシュを使用します。登録字形は全3,877件です。`src/drcs/mappings.rs` にハッシュ値とUnicode文字列だけを保持し、参照ビットマップはソース・テスト・DLLに含めません。

ハッシュは初期値 `0xcbf29ce484222325` に対し、`[width, height, bits_per_pixel, mode, depth]` の5バイト、続いて受信したビットマップの全バイトを順に処理します。各バイトでXORした後、`0x100000001b3` を乗算し、64bitで折り返します。寸法やビット深度に加え、mode・depthの違いも区別します。可変の外字コードやfont_idは含めません。対応表はハッシュの昇順の静的配列で、二分探索します。3,877件でも検索は最大12回程度の比較で済み、動的な検索表の初期化やメモリー確保は不要です。

ハッシュ衝突の可能性はあります。登録時にはローカル資料との照合とキー重複検査を行います。画像の類似判定は行いません。

全件のハッシュ・Unicode対応は [mappings.rs](mappings.rs) を参照してください。

複数文字のUnicode文字列を代替表記として使う場合も、元のDRCSは1セルとして扱います。

## 表示フォントと代替字形

表示にはNoto Sans JPとNoto Sans Symbols 2を想定しています。漢字（𠮷・髙・﨑などの異体字を含む）・括弧（二重丸括弧・二重かぎ括弧・二重山括弧）・ローマ数字（Ⅰ・Ⅴ）・面積単位（㎢）・☎・音符・三点リーダー・⤵はNoto Sans JP、その他の矢印・機器・耳・音・発話する横顔の記号はNoto Sans Symbols 2を想定しています。フォントの読み込みと描画は受信側で行います。

画面、電話、スピーカーなどの機器記号は意味を優先した代替です。パソコンは「🖳」、携帯電話は「🖁」、無線機器候補は「📻」、左右の声・音は「🔊」、受話器・着信音は「☎」へ変換します。スピーカーの波線数、音の方向、耳に付随する放射線、機種の細部は再現しません。発話する横顔は「🗣」へ変換しますが、顔の輪郭や口から出る線の細部はフォントに従います。無線機器候補の用途は推定です。

折れ曲がる矢印は対応文字で方向を保持しますが、角形・曲線形などの形状は異なる場合があります。面積単位は「㎢」へ変換します。リボン・蝶ネクタイの記号は「🎀」へ変換し、輪郭や付随する線の細部はフォントに従います。漢字の細部の異体字形や三点リーダーの高さは、受信側のフォントに従います。

## データの管理

- この説明ファイルと `src/drcs/mappings.rs` のハッシュ対応表はGit管理対象です。実行時に収集フォルダーや元画像を読み込むことはありません。
- 収集・録画解析用ソースは `tools/drcs/` にあり、指定したfeatureを有効にした場合だけ使用します。手順は [tools/drcs/README.md](../../tools/drcs/README.md) を参照してください。
- 開発用のBMP・JSON・録画はGit管理対象に含めません。`drcs-unmapped/` はGit管理から除外しています。このディレクトリーでは `README.md` と `mappings.rs` 以外は除外します。

## 検証

通常の `cargo test` は人工的なビット列でハッシュ仕様、属性の区別、定義解析、未知文字への再定義、不完全データを検証します。ローカルの収集資料や外部の置換JSONには依存しません。
